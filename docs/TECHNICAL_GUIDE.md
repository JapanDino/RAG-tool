# Техническая документация: помощник курса Canvas

Версия: LTI-пилот, сентябрь 2026. Аудит и фактические результаты запусков: [отчёт проверки](PILOT_VERIFICATION.md). Инструкции для учеников и преподавателей: [руководство пользователя](USER_GUIDE.md).

## Назначение и состав продукта

Помощник открывается из курса Canvas и связывает учебные материалы, рекомендованную литературу, ответы на вопросы, предварительный анализ по таксономии Блума и обратную связь. Все учебные данные ограничены текущим курсом. Вход ученика не требует отдельного пароля.

В проекте два интерфейса:

- **Портал `/portal`** — продукт для пилота Canvas: ученик и преподаватель, управление доступом на сервере.
- **Studio `/`** — локальные инструменты автора и исследователя: анализ текста, граф знаний, разметка, поиск, датасеты и метрики. Эти функции не предоставляются ученику через LTI. В `APP_MODE=lti` старые API закрыты; отдельный Docker-образ frontend для LTI перенаправляет `/` на `/portal`.

## Соответствие исходным требованиям

| Требование | Реализация | Ограничение |
|---|---|---|
| Подключение к Canvas по LTI | LTI 1.3 / OIDC, Course Navigation, подписанный вход | Одна платформа, Client ID и Deployment ID на установку; запуск в новой вкладке |
| Анализ материалов курса по Блуму | Распределение уровней и примеры фрагментов | Эвристика по глаголам; не полноценная педагогическая экспертиза и не измерение знаний |
| Чат ученика | Вопросы и уточнения, поиск по опубликованным источникам, цитаты, чтение материала | Ответы модели могут ошибаться; проверка ID источника не доказывает смысловую точность |
| Рекомендованная литература | Загрузка PDF/TXT/MD/DOCX, просмотр текста и иллюстраций, публикация, скрытие, удаление; скачивание новых оригиналов PDF/DOCX | Нет загрузки книги по URL и OCR сканов; в просмотре структура упрощена, оригинал доступен отдельным файлом |
| Материалы Canvas | Ручной импорт опубликованных страниц | Нет автоматического импорта вложений, заданий, тестов и обсуждений |
| Обратная связь | Оценка материала и необязательный комментарий | Преподаватель видит агрегаты, без имён; свободные комментарии ему не выдаются |
| Метрики преподавателя | Вопросы, ответы с источниками, нехватка контекста, ошибки | Совокупные счётчики, без индивидуальной статистики и периода в интерфейсе |

Слово «анонимный» здесь означает «без имени в записи отзыва и без имени в кабинете преподавателя». Сессии, инфраструктурные журналы и содержание комментария не позволяют обещать полную техническую анонимность.

## Архитектура и потоки данных

Браузер обращается к Next.js через один HTTPS-origin. Next.js пересылает `/lti/*` и `/api-proxy/*` в FastAPI. PostgreSQL с pgvector хранит материалы, фрагменты, векторы и сводные данные; Redis хранит сессии и ограничители запросов. Локальная embedding-модель создаёт векторы; OpenAI-совместимый сервис Letovo генерирует ответ. Celery используется исследовательскими сценариями Studio; операции пилота выполняются синхронно.

### Вход

1. Canvas передаёт `iss`, `login_hint`, `target_link_uri` в `/lti/login`.
2. Сервер создаёт state и nonce на 5 минут, ставит защищённый cookie и перенаправляет браузер на авторизацию Canvas.
3. Canvas отправляет подписанный `id_token` на `/lti/launch`.
4. Сервер проверяет подпись RS256 по настроенному JWKS платформы, issuer, audience/azp, время, nonce, deployment, тип сообщения, resource link, контекст и разрешённый номер курса. State используется один раз и связан с браузером.
5. Контекст курса связывается с отдельным датасетом. Сессия на 1 час сохраняется в Redis, непрозрачный токен передаётся странице запуска и помещается в sessionStorage.
6. Портал получает свою роль и материалы по Bearer-токену. Клиент не выбирает course ID или dataset ID.

Поддержанные роли: Learner → ученик, Instructor и ContentDeveloper → преподаватель. TeachingAssistant, Observer и остальные роли не предоставляют доступ автоматически.

### Материал и ответ

1. Преподаватель загружает файл или запускает импорт страницы Canvas.
2. Сервер извлекает текст, делит его на фрагменты примерно по 1500 символов с перекрытием 150, вычисляет векторы и сохраняет черновик.
3. После просмотра преподаватель публикует материал для всех участников пилотного курса.
4. Вопрос ищется среди опубликованных готовых фрагментов с совместимой моделью векторов. Из 8 кандидатов отбирается до 6 источников с учётом порога сходства и доступности Canvas.
5. Модель получает вопрос, до 6 последних сообщений и источники. Приложение проверяет формат ответа и допустимость ID цитат, а перед выдачей повторно проверяет публикацию источников.
6. При недостатке контекста или недопустимых цитатах возвращается отказ; при сбое провайдера — сообщение об ошибке. Неудавшийся вопрос можно повторно отправить из формы.

Порог `PORTAL_MIN_SIMILARITY` необходимо подбирать на контрольных вопросах конкретного курса. Он не гарантирует, что модель умеет отличать все вопросы вне темы.

Для семейств E5 small/base/large используются префиксы `passage: ` для документов и `query: ` для вопросов, в том числе на русском. Версия векторов содержит `e5-prefix-v1`: старые векторы без префиксов не смешиваются с новыми. При обновлении существующей установки нужно скрыть прежние материалы, повторно импортировать Canvas и заново загрузить литературу, проверить ответы, затем опубликовать новые копии. Автоматической переиндексации ранее загруженной литературы в портале нет. Для локальной копии E5 сохраняйте стандартное имя каталога, например `multilingual-e5-small` или `e5-small`.

Перед первым использованием прогрейте `/health` и убедитесь, что `semantic=true`. Загрузка весов может занимать несколько минут; недоступная модель приводит к отказу поиска, а не к выдаче случайного ответа. Проверка локально выполнена с `multilingual-e5-small`; производительность модели `large`, указанной по умолчанию, на сервере школы ещё нужно измерить.

## Контракт API пилота

### Изображения из PDF/DOCX

При новой загрузке PDF извлекаются встроенные растровые XObject-изображения с номером страницы и её текстом. В DOCX читаются встроенные изображения основного документа (включая таблицы), alt-подписи и соседние абзацы. Не загружаются внешние URL; SVG/EMF, векторные PDF-схемы, inline PDF-изображения и изображения в колонтитулах DOCX не поддерживаются. OCR и визуальное понимание рисунка не добавлены.

Картинки нормализуются в PNG, метаданные удаляются, размер ограничивается 1600 px по длинной стороне. Лимиты: 20 иллюстраций, 12 млн пикселей и 5 МБ входных данных на изображение, суммарно до 10 МБ нормализованных изображений на материал. Неподдерживаемые/слишком большие картинки пропускаются со счётчиком в результате загрузки; читаемый текст сохраняется. Файл без текста по-прежнему отклоняется.

Для поиска создаются отдельные фрагменты с подписью/контекстом картинки. Они не дублируются в текстовом просмотре и не увеличивают распределение Блума. Модель получает только текст и метаданные, выбирает до трёх иллюстраций из найденных фрагментов; сервер принимает лишь существующие ID, связанные с процитированными фрагментами. При отсутствии подходящей иллюстрации ответ остаётся текстовым. Релевантность подбора по контексту не равна анализу пикселей и требует проверки преподавателем.

Миграция `0020_portal_images.sql` добавляет `portal_images` и `portal_files`. PNG и оригиналы новых PDF/DOCX хранятся в PostgreSQL как BYTEA, удаляются каскадно с материалом и входят в резервную копию БД. Дополнительное файловое хранилище не нужно. Старые загрузки необходимо загрузить заново: их исходные файлы прежде не сохранялись.

Получение картинки и оригинала требует Bearer-сессии, доступа к курсу и опубликованного материала (преподавателю доступны черновики). Ответы имеют `Cache-Control: no-store`; токены не помещаются в URL. Frontend загружает изображения с Authorization и освобождает локальные blob URL при закрытии. Уже полученную пользователем копию файла или показанное изображение невозможно отозвать задним числом.

В таблице указаны серверные пути. Из браузера `/portal/...` вызываются как `/api-proxy/portal/...`.

| Метод и путь | Кто вызывает | Назначение |
|---|---|---|
| GET `/lti/config` | Администратор Canvas | JSON для регистрации |
| GET `/lti/jwks` | Canvas | Публичный ключ инструмента |
| GET/POST `/lti/login` | Canvas | Начало OIDC |
| POST `/lti/launch` | Canvas | Проверка входа и выдача страницы запуска |
| GET `/portal/session` | Обе роли | Название курса и роль |
| GET `/portal/materials` | Обе роли | Доступный список; черновики только преподавателю |
| GET `/portal/materials/{id}` | Обе роли | Извлечённые фрагменты материала |
| GET `/portal/materials/{id}/images/{image_id}` | Обе роли, с проверкой публикации | PNG иллюстрации |
| GET `/portal/materials/{id}/original` | Обе роли, с проверкой публикации | Скачать исходный PDF/DOCX |
| POST `/portal/materials` | Преподаватель | Multipart-поле `file` |
| PATCH `/portal/materials/{id}` | Преподаватель | JSON `{"published":true}` либо `false` |
| DELETE `/portal/materials/{id}` | Преподаватель | Удаление материала и связанных данных |
| POST `/portal/import-canvas` | Преподаватель | Импорт страниц и счётчики imported/skipped/remaining |
| GET `/portal/analysis` | Преподаватель | Распределение уровней, примеры, метод и лимит |
| GET `/portal/summary` | Преподаватель | Метрики и агрегированные отзывы |
| POST `/portal/chat` | Обе роли | JSON с `message` и `history`; ответ и цитаты |
| POST `/portal/materials/{id}/feedback` | Действующая сессия | JSON с `rating` и необязательным `comment` |

Ошибки: 401 — вход отсутствует или истёк; 403 — недостаточно прав; 404 — материал недоступен/другой курс; 409 — источник изменился; 413 — превышен размер; 415 — формат не поддерживается; 422 — неверный ввод; 429 — часовой лимит; 502/503 — недоступен внешний или внутренний сервис. Отзывы в интерфейсе доступны ученику; API требует действующую сессию и опубликованный материал.

## Лимиты и поведение

| Параметр | Значение |
|---|---|
| Размер файла | 10 МБ |
| Извлечённый текст | 60 000 символов на материал |
| PDF | До 40 страниц, текстовый слой |
| DOCX | XML текста до 4 МБ; извлечение с защитой от XML entities |
| Импорт Canvas | Первые 30 страниц за запуск; нет перехода к следующим 30 |
| Анализ | Первые 500 фрагментов, до 30 примеров, включая черновики |
| Вопрос | До 4000 символов |
| История запроса | До 6 сообщений, до 4000 символов каждое |
| Комментарий | До 2000 символов |
| Сессия | 1 час, без автоматического продления |
| Запросы на сессию/пользователя и курс | Чат 60/час, загрузка 20/час, импорт 5/час, отзывы 10/час |
| Скрытие малых групп | Число отзывов менее 5 не показывается |

Повторный импорт сначала снимает публикацию прежних копий Canvas, в том числе при последующей ошибке соединения. После обновления их надо проверить и опубликовать заново. Удаление в портале не удаляет исходную страницу Canvas. Удалённый файл и связанные отзывы не имеют корзины.

Отзыв не является уникальным голосом: один пользователь может оставить несколько отзывов в пределах лимита. «5 отзывов» не означает «5 разных учеников».

## Данные и эксплуатация

В PostgreSQL: `portal_courses`, `portal_materials`, `portal_images`, `portal_files`, `portal_feedback`, `portal_metrics`, а также общие `datasets`, `documents`, `chunks`, `embeddings`. Векторы хранятся как vector(1536); локальные векторы меньшей размерности дополняются нулями. Материалы разных моделей не смешиваются при поиске. Смена модели требует переиндексации материалов.

В Redis: хешированные ключи случайных session/state-токенов и счётчики запросов. Сессия содержит идентификатор субъекта LTI, роль и контекст курса. В записи отзыва нет поля пользователя. В базе приложения нет таблицы истории чата; диалог хранится в памяти страницы. Перезагрузка страницы очищает диалог, но sessionStorage может сохранить вход.

Letovo получает вопрос, ограниченную историю и найденные фрагменты. Политика хранения на стороне Letovo зависит от его администратора. Секреты находятся только в серверном окружении, не в JavaScript и не в Git. Не включать запись POST-тел и Authorization в proxy-логах.

До запуска назначить владельца эксплуатации, срок хранения материалов и отзывов, расписание резервного копирования PostgreSQL и процедуру восстановления. Автоматической политики удаления данных и панели управления ею пока нет. Redis пилота не сохраняет сессии на диск; его перезапуск завершает активные входы.

## Подключение и приёмка

Точная инструкция по Docker, HTTPS, Developer Key, Client ID и Deployment ID: [передача администратору](CANVAS_ADMIN_HANDOFF.md). Для регистрации используется JSON из `/lti/config`; каждый URL инструмента должен находиться на одном HTTPS-origin. Токен Canvas REST API настраивается отдельно от LTI. AGS, NRPS, Deep Linking и передача оценок не реализованы.

Перед общим запуском необходима приёмка на целевом сервере и настоящем тестовом курсе: вход двух реальных ролей, публикация и отзыв доступа к материалам, минимум 10 контрольных вопросов с оценкой смысла цитат, производительность импорта, доступность Letovo и embedding-модели, резервное копирование. Локальная проверка приложения и подписанного тестового запуска подтверждает работу пилота, но не заменяет эти внешние условия.

## Логичные следующие функции

Предложения, а не обещания уже реализованного:

1. **Прозрачное состояние источников:** когда обновлён материал, почему он снят с публикации, какие страницы не импортированы. Это сократит вопросы при приёмке.
2. **Фоновая индексация с прогрессом и очередью:** большие курсы не должны удерживать страницу в ожидании несколько минут.
3. **Полный импорт модулей и файлов Canvas:** с переносом ограничений доступа. Сейчас безопасный охват ограничен опубликованными копиями для всего курса.
4. **Модерируемые комментарии и защита от повторных отзывов:** помогут преподавателю понять конкретную ошибку, сохранив согласованную модель приватности.
5. **Оценка качества ответов:** «полезно / неверно», набор контрольных вопросов, доля корректных цитат и проверка педагогом.
6. **Операционная готовность:** статус зависимостей, политика хранения, восстановление из резервной копии, активный CI.
7. **Дополнительно:** добавление рекомендованных URL, метрики за период и экспорт, сохранение личной истории по выбору ученика, ручная корректировка анализа Блума. Сохранение чатов требует отдельного решения о приватности.

Начисление баллов, автоматические оценки и наблюдение за индивидуальными учениками не входят в текущие требования и не добавлены.
