# Техническая документация: помощник курса Canvas

Разметка Блума в портале: [научная основа, правила и валидация](BLOOM_METHODOLOGY.md). `GET /portal/analysis` использует `bloom_rubric.classify_learning_demands`, без вызова LLM. `method=contextual_rubric_rules`, `rubric_version=rbt-context-1.0`; добавлены `knowledge_distribution`, `statuses`, `references`, а в примерах — `chunk_id`, `evidence` с цитатой/правилом и `rationale`. Поле `levels` может быть пустым. Счётчики относятся к фрагментам, не уникальным заданиям. Миграция не нужна; пересобрать backend/frontend, установить обновлённые зависимости. Docker-набор теперь включает `pymorphy3` и русский словарь. Модуль задаёт путь к словарю явно и не зависит от старого механизма `pkg_resources`.

Загрузка текстов в портал сохраняет абзацы и короткие инструкции; HTML-экстрактор различает блоки и встроенное форматирование. Прежние копии не переписываются автоматически: для восстановления структуры нужен повторный импорт/загрузка. PDF-разбиение по страницам остаётся прежним. Исследовательский Studio-классификатор сохранён отдельно и не получает статус научно валидированного.

Версия: LTI-пилот, сентябрь 2026. Аудит и фактические результаты запусков: [отчёт проверки](PILOT_VERIFICATION.md). Инструкции для учеников и преподавателей: [руководство пользователя](USER_GUIDE.md).

Модель продукта, состояния объектов и предложения развития: [PRODUCT_LOGIC.md](PRODUCT_LOGIC.md). В повторном UX-аудите добавлены обновление `/preferences` при возврате в чат/окно, сброс локального согласия при отключении журнала, повтор загрузки настроек, обновление библиотеки без потери диалога и понятные сетевые ошибки. Форма отзыва отправляет только `rating`; совместимость backend с прежним полем `comment` сохраняется, ранее сохранённые комментарии преподавателю не выдаются. Миграция для этих изменений не нужна.

## Назначение и состав продукта

Помощник открывается из курса Canvas и связывает учебные материалы, рекомендованную литературу, ответы на вопросы, предварительный анализ по таксономии Блума и обратную связь. Все учебные данные ограничены текущим курсом. Вход ученика не требует отдельного пароля.

В проекте два интерфейса:

- **Портал `/portal`** — продукт для пилота Canvas: ученик и преподаватель, управление доступом на сервере.
- **Studio `/`** — локальные инструменты автора и исследователя: анализ текста, граф знаний, разметка, поиск, датасеты и метрики. Эти функции не предоставляются ученику через LTI. В `APP_MODE=lti` старые API закрыты; отдельный Docker-образ frontend для LTI перенаправляет `/` на `/portal`.

## Соответствие исходным требованиям

| Требование | Реализация | Ограничение |
|---|---|---|
| Подключение к Canvas по LTI | LTI 1.3 / OIDC, Course Navigation, подписанный вход | Одна платформа, Client ID и Deployment ID на установку; запуск в новой вкладке |
| Анализ материалов курса по Блуму | Учебные действия, типы знания, цитаты и правила, воздержание при нехватке контекста | Рубрика `rbt-context-1.0`; научная основа не заменяет независимую валидацию реализации |
| Чат ученика | Вопросы и уточнения, поиск по опубликованным источникам, цитаты, чтение материала | Ответы модели могут ошибаться; проверка ID источника не доказывает смысловую точность |
| Рекомендованная литература | Загрузка PDF/TXT/MD/DOCX, просмотр текста и иллюстраций, публикация, скрытие, удаление; скачивание новых оригиналов PDF/DOCX | Нет загрузки книги по URL и OCR сканов; в просмотре структура упрощена, оригинал доступен отдельным файлом |
| Материалы Canvas | Фоновый импорт страниц и PDF/DOCX/TXT/MD, модули, порядок, прогресс, отчёт по элементам | До 300 материалов; задания/тесты/обсуждения и ограниченные модули пропускаются |
| Учебный режим | Упражнение по источникам → попытка → проверка и подсказка → повтор → разрешённое решение | Без оценок Canvas; проверка ИИ не является аттестацией |
| Контроль качества | Добровольный журнал вопросов и ответов без ID ученика; очистка имён/контактов, оценки и статусы просмотра | Автоматическое обезличивание не гарантирует анонимность по содержанию |
| Личная работа | Потоковый ответ, остановка, повтор, локальная история и заметки по выбору ученика | История привязана к браузеру, не синхронизируется между устройствами |
| Обратная связь | Оценка материала и необязательный комментарий | Преподаватель видит агрегаты, без имён; свободные комментарии ему не выдаются |
| Метрики преподавателя | Вопросы, ответы с источниками, нехватка контекста, ошибки | Совокупные счётчики, без индивидуальной статистики и периода в интерфейсе |

Слово «анонимный» здесь означает «без имени в записи отзыва и без имени в кабинете преподавателя». Сессии, инфраструктурные журналы и содержание комментария не позволяют обещать полную техническую анонимность.

## Архитектура и потоки данных

Браузер обращается к Next.js через один HTTPS-origin. Next.js пересылает `/lti/*` и `/api-proxy/*` в FastAPI. PostgreSQL с pgvector хранит материалы, фрагменты, векторы и сводные данные; Redis хранит сессии и ограничители запросов. Локальная embedding-модель создаёт векторы; OpenAI-совместимый сервис Letovo генерирует ответ. Celery используется исследовательскими сценариями Studio. Расширенный импорт пилота выполняется через FastAPI BackgroundTasks с отдельной сессией БД и сохранённым статусом; чат использует потоковый HTTPX-клиент. Отдельный брокер задач для импорта не требуется.

### Вход

1. Canvas передаёт `iss`, `login_hint`, `target_link_uri` в `/lti/login`.
2. Сервер создаёт state и nonce на 5 минут, ставит защищённый cookie и перенаправляет браузер на авторизацию Canvas.
3. Canvas отправляет подписанный `id_token` на `/lti/launch`.
4. Сервер проверяет подпись RS256 по настроенному JWKS платформы, issuer, audience/azp, время, nonce, deployment, тип сообщения, resource link, контекст и разрешённый номер курса. State используется один раз и связан с браузером.
5. Контекст курса связывается с отдельным датасетом. Сессия на 1 час сохраняется в Redis, непрозрачный токен передаётся странице запуска и помещается в sessionStorage.
6. Портал получает свою роль и материалы по Bearer-токену. Клиент не выбирает course ID или dataset ID.

Поддержанные роли: Learner → ученик, Instructor и ContentDeveloper → преподаватель. TeachingAssistant, Observer и остальные роли не предоставляют доступ автоматически.

### Материал и ответ

1. Преподаватель загружает файл или запускает импорт страницы Canvas.
2. Сервер извлекает текст, делит его на фрагменты примерно по 1500 символов с перекрытием 150, вычисляет векторы и сохраняет черновик.
3. После просмотра преподаватель публикует материал для всех участников пилотного курса.
4. Вопрос ищется среди опубликованных готовых фрагментов с совместимой моделью векторов. Из 8 кандидатов отбирается до 6 источников с учётом порога сходства и доступности Canvas.
5. Модель получает вопрос, до 6 последних сообщений и источники. Приложение проверяет формат ответа и допустимость ID цитат, а перед выдачей повторно проверяет публикацию источников.
6. При недостатке контекста или недопустимых цитатах возвращается отказ; при сбое провайдера — сообщение об ошибке. Неудавшийся вопрос можно повторно отправить из формы.

Порог `PORTAL_MIN_SIMILARITY` необходимо подбирать на контрольных вопросах конкретного курса. Он не гарантирует, что модель умеет отличать все вопросы вне темы.

Для семейств E5 small/base/large используются префиксы `passage: ` для документов и `query: ` для вопросов, в том числе на русском. Версия векторов содержит `e5-prefix-v1`: старые векторы без префиксов не смешиваются с новыми. При обновлении существующей установки нужно скрыть прежние материалы, повторно импортировать Canvas и заново загрузить литературу, проверить ответы, затем опубликовать новые копии. Автоматической переиндексации ранее загруженной литературы в портале нет. Для локальной копии E5 сохраняйте стандартное имя каталога, например `multilingual-e5-small` или `e5-small`.

Перед первым использованием прогрейте `/health` и убедитесь, что `semantic=true`. Загрузка весов может занимать несколько минут; недоступная модель приводит к отказу поиска, а не к выдаче случайного ответа. Проверка локально выполнена с `multilingual-e5-small`; производительность модели `large`, указанной по умолчанию, на сервере школы ещё нужно измерить.

## Контракт API пилота

### Структурированные ответы и схемы

Ответ `/portal/chat` сохраняет `answer`, `citations`, `images` и дополняется `sections` и `diagram`. До четырёх разделов содержат заголовок, объяснение, до шести пунктов и ID подтверждающих фрагментов. Схема содержит 2–6 узлов, 1–8 направленных связей и источники. Сервер ограничивает размеры, проверяет ID узлов и принадлежность цитат подтверждённому ответу. Некорректный дополнительный блок отбрасывается; проверенный основной ответ остаётся доступным. Проверка ID не доказывает фактическую точность объяснения — остаётся необходимость сверки с материалами.

Интерфейс отображает данные средствами React/CSS, без выполнения HTML, SVG или Mermaid от модели. Схема помечена как составленная помощником по материалам, у схемы и разделов есть кнопки источников. На мобильном экране связи располагаются вертикально. Кнопки продолжения заполняют поле вопроса; отправка требует обычного нажатия «Отправить». Запрос принимает необязательный `response_style`: `auto`, `simple`, `steps`, `diagram`, `check`. Устаревающий контракт `check` сохранён для внешних клиентов; UI использует отдельный `/study`. В режиме `check` сервер убирает иллюстрации, разделы и схему, чтобы они не подсказывали ответ, а модель получает инструкцию задать один вопрос. При ручном редактировании поля применяется `auto`. История следующих запросов включает текст ответа и разделов в пределах прежнего лимита 4000 символов на сообщение. Бюджет ответа модели — 2600 токенов.

### Иллюстрации со страниц Canvas

При импорте HTML-страницы обрабатываются первые 20 `img`: ссылки на файлы того же Canvas разрешаются через `/api/v1/courses/{course_id}/files/{id}`. Подпись берётся из alt/figcaption, контекст — из соседнего текста. Скрытые, заблокированные, ещё не открытые и просроченные файлы не импортируются. Внешние картинки и встроенные SVG не загружаются. Отдельные PDF/DOCX обрабатываются новым импортом файлов курса. Неудачные картинки учитываются в `images_skipped`, успешные — в `images_imported`; текст страницы сохраняется.

Загрузка ограничена origin Canvas и точными HTTPS-origin из `CANVAS_FILE_ORIGINS` (через запятую). Администратор добавляет только проверенные хосты файлового хранилища школы, если Canvas перенаправляет скачивание на CDN. Каждый переход проверяется; Canvas-токен передаётся только origin Canvas. URL из HTML не скачивается напрямую, подписанные ссылки хранилища не отправляются ученику или модели. Применяются те же ограничения размера и очистка метаданных, что у PDF/DOCX.

Миграция `0021_canvas_images.sql` добавляет идентификатор и версию файла, расширяет поле отпечатка страницы. Новые импорты сравнивают полный HTML, включая изменения картинки/подписи. Перед выдачей ученику проверяются доступность и версия каждого импортированного файла. Изменение или скрытие файла снимает публикацию всей копии страницы до повторного импорта и проверки учителем. При недоступности Canvas выдача блокируется. Старые страницы следует повторно импортировать; прежние текстовые копии сохраняют совместимость. Индивидуальные условия доступа и ограничения модулей по-прежнему требуют отдельной приёмки и не воспроизводятся полностью.

Основание API: [Canvas Files: metadata и скачивание](https://developerdocs.instructure.com/services/canvas/resources/files).

### Изображения из PDF/DOCX

При новой загрузке PDF извлекаются встроенные растровые XObject-изображения с номером страницы и её текстом. В DOCX читаются встроенные изображения основного документа (включая таблицы), alt-подписи и соседние абзацы. Не загружаются внешние URL; SVG/EMF, векторные PDF-схемы, inline PDF-изображения и изображения в колонтитулах DOCX не поддерживаются. OCR и визуальное понимание рисунка не добавлены.

Картинки нормализуются в PNG, метаданные удаляются, размер ограничивается 1600 px по длинной стороне. Лимиты: 20 иллюстраций, 12 млн пикселей и 5 МБ входных данных на изображение, суммарно до 10 МБ нормализованных изображений на материал. Неподдерживаемые/слишком большие картинки пропускаются со счётчиком в результате загрузки; читаемый текст сохраняется. Файл без текста по-прежнему отклоняется.

Для поиска создаются отдельные фрагменты с подписью/контекстом картинки. Они не дублируются в текстовом просмотре и не увеличивают распределение Блума. Модель получает только текст и метаданные, выбирает до трёх иллюстраций из найденных фрагментов; сервер принимает лишь существующие ID, связанные с процитированными фрагментами. При отсутствии подходящей иллюстрации ответ остаётся текстовым. Релевантность подбора по контексту не равна анализу пикселей и требует проверки преподавателем.

Миграция `0020_portal_images.sql` добавляет `portal_images` и `portal_files`. PNG и оригиналы новых PDF/DOCX хранятся в PostgreSQL как BYTEA, удаляются каскадно с материалом и входят в резервную копию БД. Дополнительное файловое хранилище не нужно. Старые загрузки необходимо загрузить заново: их исходные файлы прежде не сохранялись.

Получение картинки и оригинала требует Bearer-сессии, доступа к курсу и опубликованного материала (преподавателю доступны черновики). Ответы имеют `Cache-Control: no-store`; токены не помещаются в URL. Frontend загружает изображения с Authorization и освобождает локальные blob URL при закрытии. Уже полученную пользователем копию файла или показанное изображение невозможно отозвать задним числом.

Отзывы в интерфейсе доступны ученику; API требует действующую сессию и опубликованный материал.

## Лимиты и поведение

| Параметр | Значение |
|---|---|
| Размер файла | 10 МБ |
| Извлечённый текст | 60 000 символов на материал |
| PDF | До 40 страниц, текстовый слой |
| DOCX | XML текста до 4 МБ; извлечение с защитой от XML entities |
| Импорт Canvas | Новый импорт: до 300 страниц и файлов; старый `/import-canvas` сохраняет лимит первых 30 страниц |
| Анализ | Первые 500 фрагментов, до 30 примеров, включая черновики |
| Вопрос | До 4000 символов |
| История запроса | До 6 сообщений, до 4000 символов каждое |
| Комментарий | До 2000 символов |
| Сессия | 1 час, без автоматического продления |
| Запросы на сессию/пользователя и курс | Чат 60/час, загрузка 20/час, импорт 5/час, отзывы 10/час |
| Скрытие малых групп | Число отзывов менее 5 не показывается |

Повторный импорт сначала снимает публикацию прежних копий Canvas, в том числе при последующей ошибке соединения. После обновления их надо проверить и опубликовать заново. Удаление в портале не удаляет исходную страницу Canvas. Удалённый файл и связанные отзывы не имеют корзины.

Отзыв не является уникальным голосом: один пользователь может оставить несколько отзывов в пределах лимита. «5 отзывов» не означает «5 разных учеников».

## Данные и эксплуатация

В PostgreSQL: `portal_courses`, `portal_materials`, `portal_images`, `portal_files`, `portal_feedback`, `portal_metrics`, а также общие `datasets`, `documents`, `chunks`, `embeddings`. Векторы хранятся как vector(1536); локальные векторы меньшей размерности дополняются нулями. Материалы разных моделей не смешиваются при поиске. Смена модели требует переиндексации материалов.

В Redis: хешированные ключи случайных session/state-токенов и счётчики запросов. Сессия содержит идентификатор субъекта LTI, роль и контекст курса. В записи отзыва нет поля пользователя. Полная личная история не хранится на сервере. При двух условиях — включённый журнал курса и явный `share_for_review=true` — в `portal_quality` попадает отдельная очищенная пара вопрос/ответ. Личная история по выбору ученика хранится в localStorage; без этого перезагрузка очищает её. sessionStorage хранит только вход.

Letovo получает вопрос, ограниченную историю и найденные фрагменты. Политика хранения на стороне Letovo зависит от его администратора. Секреты находятся только в серверном окружении, не в JavaScript и не в Git. Не включать запись POST-тел и Authorization в proxy-логах.

До запуска назначить владельца эксплуатации, срок хранения материалов и отзывов, расписание резервного копирования PostgreSQL и процедуру восстановления. Для журнала качества действует удаление по 30 календарным дням: при чтении/записи и ежечасно через lifespan сервера в APP_MODE=lti. При остановленном сервере очистка возобновляется после запуска. Политику материалов, старых отзывов, отчётов импорта и резервных копий администратор настраивает отдельно. Redis пилота не сохраняет сессии на диск; его перезапуск завершает активные входы.

## Подключение и приёмка

Точная инструкция по Docker, HTTPS, Developer Key, Client ID и Deployment ID: [передача администратору](CANVAS_ADMIN_HANDOFF.md). Для регистрации используется JSON из `/lti/config`; каждый URL инструмента должен находиться на одном HTTPS-origin. Токен Canvas REST API настраивается отдельно от LTI. AGS, NRPS, Deep Linking и передача оценок не реализованы.

Перед общим запуском необходима приёмка на целевом сервере и настоящем тестовом курсе: вход двух реальных ролей, публикация и отзыв доступа к материалам, минимум 10 контрольных вопросов с оценкой смысла цитат, производительность импорта, доступность Letovo и embedding-модели, резервное копирование. Локальная проверка приложения и подписанного тестового запуска подтверждает работу пилота, но не заменяет эти внешние условия.

## Рабочее пространство: API и хранение (миграция 0022)

| Endpoint | Доступ и контракт |
|---|---|
| GET `/portal/preferences` | Обе роли: `quality_enabled`, `allow_solutions`, `solution_after_attempts` |
| PUT `/portal/preferences` | Только преподаватель; строгий JSON, число попыток 1–5 |
| POST `/portal/chat/stream` | Как `/chat`, но NDJSON: `status`, `draft`, `result` или `error` |
| POST `/portal/study` | Тема в `message`, необязательный `context`; возвращает вопрос, ID упражнения, цитаты |
| POST `/portal/study/{id}/attempt` | Только владелец упражнения в текущем курсе; `{answer}`; до 10 попыток |
| POST `/portal/study/{id}/solution` | Только владелец; актуальное разрешение преподавателя и минимум попыток |
| GET `/portal/quality?status=open&offset=0` | Только преподаватель своего курса; 50 записей, `has_more`; status: all/open/resolved |
| PATCH `/portal/quality/{id}` | Преподаватель; `{status: "open" или "resolved"}` |
| POST `/portal/quality/{id}/feedback` | Текущая сессия того же курса + отдельный capability `feedback_key`; helpful/unclear/incorrect/wrong_source |
| POST `/portal/imports` | Преподаватель; запускает/возвращает активный импорт, отвечает `{id}` |
| GET `/portal/imports/latest` | Преподаватель; последний статус, прогресс, общее число и результаты элементов |

`context` имеет вид `{document_id, chunk_id?, quote?}`. Сервер проверяет текущий курс, публикацию, актуальность Canvas, принадлежность chunk к документу и наличие quote в его тексте. Выделение до 1800 символов. При выбранном материале поиск ограничен им; указанный фрагмент добавляется первым независимо от сходства. Номер PDF-страницы хранится в meta чанка; новые PDF делятся по страницам. Старые файлы нужно переимпортировать. Точная геометрическая подсветка внутри оригинального PDF не реализована: подсвечивается извлечённый фрагмент, оригинал открывается на странице.

Потоковое поколение сначала запрашивает массив цитат. Предварительный answer появляется только после проверки перечисленных ID на принадлежность найденным фрагментам. Полная структура, иллюстрации и схемы выдаются в `result` после повторной проверки публикации. Это проверка структуры/доступа, не семантической истинности. В случае ошибки или остановки UI удаляет черновик и возвращает вопрос. Fetch AbortController закрывает поток, HTTPX закрывает соединение с моделью; уже запущенная индексация/поиск в рабочем потоке может завершиться. Фактически потраченные токены провайдера отмена не возвращает. Если провайдер выдаёт JSON в другом порядке, предварительного текста может не быть. Nginx должен иметь `proxy_buffering off`; таймаут прокси 300 секунд. API `/chat` сохранён для клиентов без streaming.

Учебное упражнение хранится в Redis под ключом с хешем курса и LTI subject, TTL — 1 час после последней попытки. Эталон, подсказки и объяснение создаются по найденным источникам. Эталон и полный разбор не входят в публичный ответ до разрешённого запроса solution. Попытки сериализуются Redis lock; доступность источников проверяется перед каждым обращением. Модель проверки возвращает только `correct`; обратная связь формируется сервером, подсказки выдаются постепенно. Формулировки и подсказки всё равно могут ошибаться или слишком сильно раскрывать ответ. Настройка решений ограничивает упражнение, не обычный чат. Лимиты: создание 30/час, попытки 60/час; оценки в LMS не передаются.

`portal_settings` хранит две настройки, по умолчанию выключенные, и порог попыток (2). `portal_quality` содержит случайный UUID записи, course ID, календарный день, очищенные вопрос/ответ, ID документов, оценку, статус и хеш случайного feedback-key. Нет subject, user ID, псевдонима ученика или точного времени. По умолчанию `share_for_review=false`; преподавательские запросы не записываются. Обезличивание: регулярные выражения для email, URL, телефонов, @handles и английских полных имён + Natasha PER для русского текста. При сбое NER запись пропускается без сохранения оригинала. Возможны пропуски и ложные срабатывания, включая фамилии учёных. Доступ администратора БД, логи инфраструктуры и содержимое текста не позволяют обещать полную анонимность. Журнал не связывает вопросы одного ученика и не включает его ответы в упражнениях. Учитель видит каждый текст отдельно, не историю человека.

Проверять наличие `natasha` и её встроенных моделей в контейнере. Обычный чат может успешно отвечать, даже если журнал пропустил запись из-за недоступного NER; в серверном логе будет обезличенное предупреждение `Quality entry skipped`. Ключ для оценки записи выдаётся только текущему ответу в памяти вкладки, хранится в БД как SHA-256 и не выдаётся учителю. Отправка оценки снова помечает запись как требующую просмотра. Закрытие или перезагрузка страницы теряет этот ключ.

`/portal/session` добавляет `storage_scope` — хеш курса и subject. Frontend сохраняет последние 20 сообщений и заметки только при явном включении. Ключ localStorage разделён по scope и документу; Bearer и feedback-key туда не записываются. Сохраняемые сообщения содержат пользовательский текст и цитаты: это незашифрованные данные браузерного профиля. Изменение доступа не отзывает уже сохранённый текст. Сохранённая ссылка/картинка при новом открытии снова проходит серверную авторизацию.

`portal_imports` хранит статус queued/running/complete/failed, прогресс и JSON-отчёт. Новый импорт перечисляет модули, элементы, страницы и файлы через Canvas REST API; пагинация имеет общий предел 100 запросов на перечисление, включая повторы 429, и проверяет origin следующего URL. Обрабатываются PDF/DOCX/TXT/MD, по 10 МБ; у страниц извлекаются иллюстрации. Загрузка защищена allowlist origin и пределом размера. Материалы обновляются по kind + source_ref, сохраняют модуль и порядок. Новые копии всегда черновики. При запуске прежние копии Canvas снимаются с публикации, даже если дальше импорт не удался.

Модули с prerequisites, sequential progress, unlock_at, признаками блокировки или overrides пропускаются консервативно, в том числе если дата открытия уже прошла. Если материал находится в нескольких модулях, ограничение любого из них блокирует импорт. Запомненные связи модуля проверяются при последующем чтении и публикации вместе с версией страницы/файла. Это не полная реализация индивидуальных прав Canvas: требуется пилот на материалах, разрешённых всему курсу. Новые назначения и неизвестные расширения школьного Canvas требуют отдельной приёмки. Нужны права токена читать Modules, Module Items, Pages, Files и скачивать файлы.

Параллельное планирование защищено PostgreSQL advisory lock. Фоновый импорт удерживает отдельный session-level lock до завершения, предотвращая наложение повторного запуска на старый worker. После 15 минут без прогресса интерфейс считает задачу прерванной; повторный импорт начинается заново, автоматически с последнего файла не возобновляется. При завершении процесса незавершённая задача теряется, её отчёт остаётся. Это ограничение пилота BackgroundTasks; для больших установок нужна отдельная долговечная очередь. Статус complete не означает отсутствие ошибок: проверяйте детали каждого элемента.

## Следующие улучшения после пилота

Предметная оценка ответов на наборе реальных вопросов курса; полноценная поддержка индивидуальных назначений Canvas; OCR и визуальное понимание схем; постоянная очередь импорта с возобновлением; объяснение конкретных ошибок учебной попытки; ручная корректировка разметки Блума; метрики за период. Эти возможности не заявляются реализованными в текущем выпуске.
