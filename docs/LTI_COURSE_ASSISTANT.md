# Помощник курса в Canvas LMS

Рабочая концепция от 19 сентября 2026 года. Это предложение по развитию существующего проекта, а не описание уже реализованных возможностей.

После этой исходной концепции добавлен ограниченный LTI-пилот. Актуальное описание реализации и ограничений: [передача администратору](CANVAS_ADMIN_HANDOFF.md). Раздел «Что уже есть в коде» ниже сохраняет снимок состояния до этих изменений.

## Цель и сценарии

Приложение открывается внутри курса Canvas через LTI 1.3 и использует контекст курса и роль пользователя.

- Ученик задаёт вопросы по доступным ему материалам курса и рекомендованной литературе. Ответ содержит ссылки на подтверждающие фрагменты. При недостатке источников помощник сообщает об этом.
- Преподаватель подключает курс, добавляет файлы и ссылки, выбирает доступность дополнительных материалов, видит состояние обработки и обновляет базу знаний.
- Преподаватель получает анализ материалов: темы, покрытие содержания и, предварительно, распределение по уровням Блума. Рекомендации по улучшению сопровождаются примерами из источников и доступны для проверки человеком.
- Ученик может оставить отдельный отзыв о конкретном материале. Преподаватель видит сводку затруднений и обратной связи.

Нужно уточнить: означало ли распознанное «API Vitel LMS» API Canvas LMS; подразумевалась ли под анализом материалов таксономия Блума. До уточнения не проектировать дополнительные интеграции и автоматическое начисление бонусов.

## Что уже есть в коде

Проверено чтением кода, без запуска приложения:

| Основа | Реализация | Что требуется для нового сценария |
|---|---|---|
| Импорт Canvas | `backend/app/services/canvas_client.py`, `backend/app/routers/canvas.py` | Привязка к установке и курсу, права на материалы, обновления и удаление устаревшего содержимого |
| Анализ и поиск | Узлы знаний, чанки, классификация Блума, pgvector | Отдельный поиск по исходным фрагментам для ответов, сохранение адресов и версий источников |
| Чат | `backend/app/routers/chat.py`, интерфейс в `frontend/pages/index.tsx` | Контекст курса из серверной сессии, проверка доступа, подтверждаемые цитаты, ученический режим |
| Загрузка документов | Существующие документы и датасеты | Библиотека курса с ролью преподавателя, статусом обработки и правилами публикации |

В просмотренных маршрутах и моделях не обнаружены LTI-вход, разграничение ролей и модель отзывов. Сейчас Canvas использует общий `CANVAS_TOKEN`. В чате `dataset_id` приходит от клиента и необязателен: без него поиск не ограничен датасетом. Системная инструкция разрешает ответы из общих знаний и команды управления интерфейсом.

## Архитектура

Сохранить существующие FastAPI, Next.js, PostgreSQL/pgvector и очередь фоновых задач.

1. **LTI-вход:** проверка OIDC/JWT, одноразовых state/nonce, issuer, audience и deployment; создание серверной сессии с ролью и контекстом курса. Проверить запуск в iframe Canvas и работу сессии при ограничении сторонних cookies.
2. **Canvas API:** отдельная авторизация для чтения содержимого. LTI-вход не предоставляет автоматически права на обычный REST API. Для пилота допустимо ограниченное серверное подключение к одному курсу; для нескольких установок нужны изолированные настройки и полномочия.
3. **База курса:** источники Canvas и добавленные преподавателем документы → извлечение текста → чанки → индекс. Хранить исходный URL, номер страницы при наличии, версию, статус и доступность. Ссылка на книгу сама по себе не даёт её полный текст: индексировать только реально полученное содержимое.
4. **Чат:** сначала определить разрешённые источники пользователя, затем выполнить поиск и сформировать ответ с цитатами. Ограничения должны действовать и при открытии источников, поиске и экспорте. Скрытые материалы и ключи ответов не попадают в ученический контекст. Текст документов обрабатывать как данные, не как команды агенту.
5. **Кабинет преподавателя:** управление источниками, запуск анализа, проверка рекомендаций и агрегированные показатели.

Минимальные новые сущности: установка LTI, связь установки и курса Canvas с датасетом, сессия пользователя с ролью, источник курса с доступностью и версией, отдельный отзыв о материале. Права определяет сервер, а не переданный браузером идентификатор датасета.

## Обратная связь и метрики

Начать с явной формы: «понятно / сложно / есть ошибка» и необязательный комментарий к материалу. Личные диалоги не считать автоматически отзывами и не показывать преподавателю.

Для первого пилота предложен режим «без имени для преподавателя». Это не обещание полной анонимности: перед выбором полностью анонимного режима отдельно определить хранение идентификаторов, технических журналов и срок удаления данных. В сводках малых групп подавлять малые значения; свободный текст может содержать самоидентификацию.

Показатели первой версии: число вопросов, доля ответов с подтверждающими источниками, доля случаев без достаточного контекста, оценки полезности и отзывы по материалам. Темы частых вопросов — дополнительная агрегированная аналитика с заранее определёнными правилами использования диалогов. Эти показатели не доказывают освоение курса.

## Последовательность MVP

1. Один тестовый курс: LTI-запуск, роли, серверная привязка к курсу и проверка доступа во всех связанных API.
2. Источники курса: импорт Canvas и загрузка литературы преподавателем, ссылки и статусы обработки, отзыв доступа при удалении или скрытии материала.
3. Ученический чат: поиск по исходным фрагментам, проверяемые цитаты, отсутствие ответа при недостатке контекста, изоляция от команд преподавателя.
4. Анализ для преподавателя: использовать существующую классификацию Блума после уточнения требований, добавить объяснения и ручную проверку.
5. Отзывы и небольшая сводка метрик; расширение аналитики после пилота.

Приёмочные сценарии: подмена course/dataset ID не открывает другой курс; ученик не может вызвать операции преподавателя; скрытый или удалённый источник больше не участвует в поиске; вопрос вне базы вызывает честное сообщение о нехватке данных; цитата ведёт к доступному исходному фрагменту; повторный LTI launch с использованным nonce отклоняется.
