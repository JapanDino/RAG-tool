# Передача администратору Canvas: LTI-пилот

Обновление разметки Блума: пересобрать frontend/backend с текущими зависимостями (`pymorphy3` и русский словарь включены в Docker requirements). Новая миграция не требуется. Старые текстовые материалы переимпортировать для сохранения границ заданий. Перед педагогическим использованием изучить [методику и границы валидации](BLOOM_METHODOLOGY.md).

Проект: **Bloom RAG — помощник курса**. Ветка подготовки: `JD/canvas-lti-handoff`.

Это версия для ограниченного пилота и приёмки администратором. Автоматические проверки не заменяют запуск в конкретной установке Canvas. Реальные issuer, Client ID, Deployment ID, домен приложения и серверный токен Canvas должен предоставить администратор. В репозитории их нет.

## Что реализовано

| Требование | Реализация пилота | Граница проверки |
|---|---|---|
| Запуск из курса Canvas | LTI 1.3 OIDC, проверка RSA-подписи, issuer/audience/azp, срока, deployment, nonce и одноразового state, привязка к браузеру | Проверяется подписанным тестовым запуском; реальный Canvas требует приёмки |
| Ученик и преподаватель | Роли из подписанного launch; курс и датасет определяются сервером | Подмена идентификаторов и вызовы операций преподавателя учеником покрыты тестами |
| Чат по материалам | Поиск по опубликованным фрагментам текущего курса, ответ с цитатами, отказ без контекста или с недопустимыми ID источников | Поиск проверяется на PostgreSQL/pgvector; модель в тестах подменена |
| Литература преподавателя | PDF с текстовым слоем, TXT, MD, DOCX; предварительный просмотр, публикация, скрытие и удаление | До 10 МБ, 60 000 символов, 40 страниц PDF; OCR сканов в портале отключён |
| Материалы Canvas | Ручной импорт до 30 опубликованных страниц курса с прикреплёнными растровыми картинками; обновление по slug | Самостоятельные вложения PDF/DOCX, задания, тесты и обсуждения автоматически не импортируются в ученический портал; нужную литературу загружает преподаватель |
| Анализ курса | Рубрика Блума по учебным действиям, типы знания, основания и неопределённые случаи | До 500 фрагментов; автоматические предложения требуют педагогической проверки; [методика](BLOOM_METHODOLOGY.md) |
| Обратная связь | Отдельные отзывы «понятно / сложно / есть ошибка» и необязательный комментарий | Преподавателю показаны только агрегаты; значения менее пяти скрыты, свободные комментарии не выдаются |
| Метрики | Вопросы, ответы с источниками, нехватка контекста и ошибки | Отдельный добровольный журнал очищенных вопросов/ответов; личная история остаётся в браузере |

Граф знаний и расширенный исследовательский интерфейс остаются в локальном режиме Studio. В режиме `APP_MODE=lti` старые API анализа, загрузки, экспорта, управления датасетами и чат-команд недоступны. Ученикам предоставляется `/portal`.

## Область пилота и доступ к данным

- Одна установка Canvas, один Client ID и Deployment ID; разрешённые номера курсов перечислены в `LTI_ALLOWED_COURSE_IDS`.
- Поддержаны роли Learner, Instructor и ContentDeveloper. Другие роли отклоняются. Для роли TeachingAssistant нужна отдельная согласованная политика доступа.
- Для импорта используется отдельный серверный Canvas API token с доступом только к курсам пилота. LTI-вход не заменяет авторизацию Canvas REST API.
- Каждая импортированная страница или загруженная книга сначала является черновиком. Преподаватель публикует копию **для всех участников пилотного курса**. Индивидуальные сроки открытия, группы и prerequisites Canvas не воспроизводятся: материалы с такими ограничениями не публиковать.
- Перед выдачей страниц Canvas проверяются доступность, published и совпадение HTML с импортированной версией (только текста у старых копий). У импортированных иллюстраций также проверяются доступность и версия файла. При изменении или снятии публикации копия исключается. При недоступности Canvas она не выдаётся. Повторный импорт снимает публикацию всех прежних копий, включая удалённые страницы.
- Файлы преподавателя остаются доступны до скрытия или удаления в портале. Ссылка на книгу не означает загрузку её полного текста.
- Сессия действует один час; изменения состава курса вступают в силу не позднее нового LTI-входа. Экстренный отзыв всех сессий: перезапуск отдельного Redis пилота, который не сохраняет данные на диск.

## Развёртывание

Обновление рабочего пространства требует миграции `0022_learning_workspace.sql` и пересборки обоих сервисов. Новые зависимости `httpx` и `natasha` включены в requirements. Для расширенного импорта токену нужны GET Modules, Module Items, Pages, Files и скачивание файлов курса. Запуск `/portal/imports` фоновый, статус `/portal/imports/latest`; при перезапуске задачи не возобновляются автоматически. Модули с условиями доступа пропускаются; полного моделирования персональных назначений Canvas нет.

В reverse proxy отключите буферизацию (`proxy_buffering off`) для потоковых ответов. Журнал качества по умолчанию выключен, ученик отдельно включает передачу своих вопросов. Удаление записей по 30 календарным дням выполняется при обращении и ежечасно lifespan-процессом работающего backend; для резервных копий нужна отдельная политика. Упражнения хранятся в Redis один час после последней попытки, не выставляют оценок в Canvas. Настройка запрета решений относится к упражнениям, не обычному чату.

Перед школьным запуском проверьте NER на синтетическом имени/почте, отсутствие исходного текста в журнале, отзыв публикации файла и ограничения модуля, настоящий потоковый ответ через HTTPS-прокси, остановку и повтор, упражнение с двумя попытками, настройки роли преподавателя. Полное описание: [технический контракт](TECHNICAL_GUIDE.md#рабочее-пространство-api-и-хранение-миграция-0022).

Для иллюстраций со страниц Canvas требуется миграция `0021_canvas_images.sql` и право серверного токена читать `GET /api/v1/courses/:course_id/files/:id` и скачивать эти файлы. Если скачивание перенаправляется на файловое хранилище, укажите его проверенные точные HTTPS-origin через запятую в `CANVAS_FILE_ORIGINS` (пример: `https://school-files.example.org`). По умолчанию разрешён только origin Canvas. Токен Canvas не передаётся стороннему хосту. Повторно импортируйте страницы, проверьте число извлечённых/пропущенных картинок и опубликуйте нужные копии.

Схемы в ответах строятся интерфейсом из ограниченного JSON модели, дополнительный сервис визуализации не требуется. Они помечены как составленные помощником; проверка ссылок на источники не заменяет предметную проверку преподавателем.

Нужен сервер с Docker Compose, постоянным хранилищем, HTTPS-доменом и доступом к Canvas, Letovo и репозиторию embedding-модели. Для первой установки резервировать от 8 ГБ RAM и достаточное место для PyTorch, образов и модели; фактический расход измерить на пилоте.

Обработка иллюстраций требует миграции `0020_portal_images.sql` (штатный запуск применяет все миграции). Картинки и оригиналы новых PDF/DOCX хранятся в БД; учтите увеличение резервных копий. Старые документы загружаются заново для извлечения картинок. Дополнительных ключей модели или сервисов для этого не требуется.

После запуска прогреть `/api-proxy/health`: ответ должен содержать `semantic: true`. Первый запуск скачивает веса и может быть долгим. При обновлении со старой версии E5 без `e5-prefix-v1` прежние векторы несовместимы: скрыть старые материалы, повторить импорт Canvas и загрузку литературы, проверить поиск и опубликовать новые копии. Подробности и эксплуатационные ограничения: [техническая документация](TECHNICAL_GUIDE.md). Инструкция для участников курса: [руководство пользователя](USER_GUIDE.md).

1. Получить ветку или проверенный commit. Работать в отдельном каталоге и отдельной БД, не поверх исследовательской базы.
2. Скопировать `deploy/lti.env.example` в `backend/.env`. Заполнить домены, URL платформы, Canvas token, Letovo key и разрешённые курсы. Для `DB_PASS` использовать длинный случайный пароль из букв и цифр (он включается в URL БД). `LTI_CLIENT_ID` и `LTI_DEPLOYMENT_ID` заполняются после регистрации. Не использовать ключи из переписки.
3. Выполнить на сервере Linux:

```bash
mkdir -p secrets
chmod 700 secrets
docker compose --env-file backend/.env -f docker-compose.lti.yml build
docker compose --env-file backend/.env -f docker-compose.lti.yml run --rm --no-deps \
  -v "$PWD/secrets:/app/secrets:rw" backend \
  python /app/scripts/generate_lti_keys.py /app/secrets
docker compose --env-file backend/.env -f docker-compose.lti.yml up -d
```

Генератор откажется перезаписывать существующие ключи. Приватный ключ остаётся в `secrets/`, публичный JWKS доступен по `/lti/jwks`. AGS, NRPS, Deep Linking и передача оценок в этой версии не используются.

4. Настроить HTTPS reverse proxy по `deploy/nginx-lti.conf.example`. Порт frontend открыт только на `127.0.0.1:3000`; БД, Redis и backend не публикуют порты. Не добавлять публичные порты к ним. Все URL приложения — на одном origin.
5. Проверить `https://<домен>/lti/config` и `/lti/jwks`. `/api-proxy/datasets` должен возвращать 404, `/api-proxy/portal/session` без сессии — 401.

`docker-compose.lti.yml` — самостоятельный файл, его не объединяют с `docker-compose.yml`. Последний предназначен для локальной разработки. В образ не копируются `.env`, `secrets/`, PEM и KEY. Для доступа к Letovo предпочтителен школьный HTTPS-шлюз: предоставленный исходный endpoint использует HTTP.

## Регистрация в Canvas

1. В администрировании Canvas создать **LTI Developer Key**. Способ конфигурации — JSON URL: `https://<домен>/lti/config` (либо вставить JSON с этого адреса).
2. Указать Redirect URI: `https://<домен>/lti/launch`. OIDC initiation URL: `https://<домен>/lti/login`; Target link URI: `https://<домен>/lti/launch`; Public JWK URL: `https://<домен>/lti/jwks`.
3. Разрешённые LTI scopes оставить пустыми. Placement — **Course Navigation**, запуск в новой вкладке (`windowTarget: _blank`). Это устраняет зависимость от сторонних cookies и хранилища iframe.
4. Custom field: `canvas_course_id=$Canvas.course.id`. Поставляется в JSON-конфигурации. Не заменять его номером другого курса.
5. Включить Developer Key, скопировать Client ID в `LTI_CLIENT_ID`.
6. В тестовом курсе установить External App по Client ID. Получить Deployment ID именно этой установки и записать его в `LTI_DEPLOYMENT_ID`.
7. Проверить issuer, Authorization URL и Canvas JWKS URL по данным вашей установки. Не путать JWKS платформы, которым проверяются входящие токены, с JWKS нашего инструмента.
8. Пересоздать backend с обновлённым окружением:

```bash
docker compose --env-file backend/.env -f docker-compose.lti.yml up -d --force-recreate backend
```

При несовпадении идентификаторов или неподдержанной роли инструмент отказывает во входе, не переключается в режим без авторизации.

## Приёмка в школьной среде

- Преподаватель входит из тестового курса и видит кабинет своего курса.
- Импортирует страницу и загружает небольшую книгу; проверяет извлечённый текст, затем публикует.
- Настоящая тестовая учётная запись ученика видит только опубликованные материалы. Не ограничиваться Canvas Student View, особенности которого могут отличаться от обычного LTI-входа.
- Вопрос по материалу получает понятный ответ и правильную цитату. Вопрос вне содержания получает отказ. Проверить не менее 10 вопросов, включая неоднозначные и провокационные инструкции в документах; ссылки на существующий фрагмент сами по себе не гарантируют смысловую правильность ответа.
- Скрытая в портале страница исчезает из чтения и поиска. Изменённая, удалённая или снятая с публикации страница Canvas перестаёт выдаваться, пока преподаватель не обновит и не опубликует копию.
- Ученик не может загрузить/опубликовать материал, увидеть сводку, анализ или другой курс даже прямым HTTP-запросом.
- Отзыв о материале хранится отдельно. Журнал качества выключен по умолчанию; после включения курса и согласия ученика преподаватель видит очищенные пары вопросов/ответов без ID пользователя.
- Отдельно проверить ответ Letovo с сервера развёртывания, загрузку настоящей embedding-модели, тайм-ауты, одновременные запросы и повторный вход по окончании часа.

До прохождения этих сценариев не объявлять версию готовой для всех учеников.

## Обработка данных и обслуживание

В PostgreSQL хранятся копии материалов, их фрагменты/векторы, отзывы без поля пользователя и дневные счётчики. В Redis — одноразовые state (5 минут), сессии и ограничители частоты (1 час). Имя и email не требуются. Субъект LTI присутствует в сессии для прав и ограничения частоты, но не записывается в отзывы.

Это режим «без имени для преподавателя», а не гарантия полной анонимности. Инфраструктурные журналы могут позволять корреляцию; свободный комментарий может содержать личные данные. Преподавателю свободные комментарии не выдаются. Для пилота согласовать срок удаления отзывов и материалов, резервное копирование и правила доступа администратора БД.

Приложение не хранит полную личную историю на сервере и не пишет её в access logs. Добровольный журнал качества сохраняет очищенные вопросы/ответы без ID ученика и точного времени; автоматическая очистка имён/контактов не гарантирует полной анонимности. Вопрос, последние сообщения текущего диалога и найденные фрагменты передаются Letovo; журналы и хранение на стороне Letovo определяются его администратором. Кнопка очистки удаляет диалог из браузера; уже переданные записи журнала она не отзывает. Локальное сохранение последних 20 сообщений и заметок включается отдельно. Не включать журналирование заголовков Authorization и POST-тела `/lti/launch` на reverse proxy.

## Автоматические проверки

См. `docs/PILOT_VERIFICATION.md` для фактического результата и известных ограничений. Тесты не используют реальные ключи или учебные материалы. Для запуска интеграционных тестов нужна отдельная БД с именем строго `portal_test`:

```bash
export PORTAL_TEST_DATABASE_URL=postgresql+psycopg://postgres:<test-password>@localhost:55432/portal_test
export PORTAL_TEST_REDIS_URL=redis://localhost:56379/0
python -m pytest -q
cd frontend
npm ci
npm run build
npm audit --omit=dev
```

Без переменной БД интеграционные тесты явно пропускаются. Проверки подписи и ролей работают без реального Canvas. Шаблон CI с PostgreSQL/pgvector и Redis находится в `deploy/github-actions-pilot.yml`. Администратор с разрешением GitHub `workflow` может перенести его в `.github/workflows/pilot.yml`; текущий токен публикации такого разрешения не имеет. Автоматический CI в этой ветке не активирован.
