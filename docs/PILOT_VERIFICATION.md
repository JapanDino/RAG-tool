Основной финальный backend-прогон выполнен на Python 3.12 с актуальными диапазонами зависимостей проекта. Браузерные проверки выполнены Playwright в установленном Chrome с эмуляцией мобильного размера; это не отдельная проверка Safari на физическом iPhone. В шаблоне CI предусмотрены Chromium и те же сценарии; шаблон не активирован.

В тестах LTI подписи настоящие RSA, но ключ платформы и launch создаются тестом. В тестах поиска используются синтетические векторы, а ответы модели и Canvas API подменены. Браузерные тесты проверяют интерфейс через подменённый API; настоящий backend отдельно покрывают интеграционные тесты. Короткий реальный запрос Letovo не доказывает качество ответов на учебные вопросы.

Светлый интерфейс и скриншоты: [обзор UX](INTERFACE.md). После редизайна повторены production build и браузерные проверки; backend в этом изменении не менялся.

## Исправлено при подготовке

- Добавлены LTI 1.3, серверные сессии и отдельный портал курса; Studio API закрыт в режиме LTI.
- Добавлены преподавательские публикация/скрытие/удаление материалов, импорт страниц и обработка DOCX как документа, а не ZIP-байтов.
- Чат ищет только в опубликованных материалах курса, показывает цитаты и не принимает придуманные ID источников. Команд управления преподавательским интерфейсом в ученическом чате нет.
- Добавлены отзывы без поля пользователя и агрегированные счётчики без хранения текстов диалогов.
- Исправлена прокрутка портала, которую блокировали глобальные стили Studio; уточнены зависимости React hooks в старом интерфейсе.
- Убрано отключение проверки TLS-сертификатов при сборке backend. `.env` и ключи исключены из контекста Docker.
- Обновлены Next.js, PostCSS/nanoid, FastAPI/Starlette и уязвимые библиотеки разбора документов/HTTP. Qwen-специфичная команда `/no_think` больше не добавляется в JSON-запросы к DeepSeek и Gemma.
- Подготовлен шаблон CI для backend, frontend, browser tests и npm security audit в `deploy/github-actions-pilot.yml`. GitHub отклонил создание workflow текущим OAuth-токеном без разрешения `workflow`, поэтому активация оставлена администратору.

## Что остаётся на приёмку администратора

1. Регистрация реального LTI Developer Key, установка приложения и проверка запуска из школьного Canvas под двумя отдельными учётными записями.
2. Сборка полного Docker-образа и запуск на целевом сервере, HTTPS/reverse proxy, проверка доступа сервера к Canvas/Letovo и веса embedding-модели.
3. Настоящая семантическая модель и качество retrieval на курсе. Подобрать порог `PORTAL_MIN_SIMILARITY`, проверить ответы и источники на контрольных вопросах.
4. Нагрузка, длительность импорта, резервное копирование, правила хранения материалов/отзывов и журналы внешнего LLM-сервиса.
5. Проверить, что публикуемые материалы разрешены всем участникам курса: индивидуальные ограничения Canvas не переносятся в портал.

В начальной попытке Letovo отвечала тайм-аутом; при повторной проверке запрос прошёл. Поэтому доступность и задержки обязательно повторно проверить с сервера школы.

Статус: **подготовлено для технической приёмки ограниченного пилота**, не заявление о готовности к эксплуатации всеми учениками и не сертификация LTI. Полный порядок установки и ограничения: [инструкция администратору](CANVAS_ADMIN_HANDOFF.md).
