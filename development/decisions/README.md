# Architecture decision records

Create an ADR only when a decision changes a durable system boundary, data model,
security posture, integration contract, or hard-to-reverse technology choice.

Do not create ADRs for routine implementation details.

Naming:

    ADR-0001-short-decision-name.md

Statuses:

- proposed;
- accepted;
- superseded;
- rejected.

Use `ADR-TEMPLATE.md` and link superseding decisions in both directions.
